# OPEN CITY — 从任务出发的公共服务门户

独立中文公共服务概念站。首屏采用**居中搜索门户**，紧接六项服务目录；城市动态、办事预约、常见问题和页尾构成完整网站。所有机构、地址与活动均为虚构，预约只生成当前页面内存中的摘要。

## 运行与构建

在仓库根目录执行：

```bash
npm ci
npm run dev -- --mode civic
npm run build -- --mode civic
```

开发端口 `5183`，独立构建产物 `dist/civic`。`index.html` 为独立入口，`src/main.tsx` 包含本网站状态和结构，`src/styles.css` 是本站独立样式。没有目录站页面壳，也不依赖其他样例的 CSS。

## 阅读源码与复刻顺序

| 区域           | 源码入口                                    | 实际职责                                               |
| -------------- | ------------------------------------------- | ------------------------------------------------------ |
| 公共说明与导航 | `public-banner`、`site-header`、`menuOpen`  | 明示虚构身份；手机导航支持展开、关闭和 Escape 返回按钮 |
| 居中搜索       | `hero-search`、`query`、`showResults`       | 输入任务关键词，跳至并聚焦目录区域                     |
| 服务目录       | `services`、`categories`、`filtered`        | 六服务、五筛选项；查询与分类取交集，数量和空态同步     |
| 城市动态       | `updates`、`activeUpdate`                   | 三类公告的实际展开/收起                                |
| 预约           | `pickService`、`submitBooking`、`cityToday` | 选服务后预填并聚焦控件；双重日期校验、确认和错误焦点   |
| 结果           | `confirmation`、`confirmationRef`           | 展示服务、日期、时段、本地未发送状态；重新安排返回表单 |
| FAQ            | 原生 `details/summary`                      | 键盘可操作的说明与演示边界                             |

1. **定义任务，而非部门。** 六项服务以居住、健康、出行、学习、公园和工作命名；数据包含稳定 ID、分类、说明与预计咨询时长。
2. **优先完成目录。** 先显示六项服务，再添加搜索与分类。用同一个 `filtered` 同时计算卡片与数量，避免数字与内容不一致。
3. **建立门户首屏。** 大标题居中，搜索位于视觉中心；不使用左文右图营销 hero。服务目录紧跟搜索区，桌面首屏可看到第一行服务卡片。
4. **保留必要上下文。** 搜索表单有明确 label；搜索提交后聚焦服务区域。卡片选择则聚焦预约中的服务 select，两条路径目标不同。
5. **闭合表单状态。** 输入 → 原生校验 → 提交函数复核 → 内存摘要。错误信息就近出现并获得焦点；编辑后清除旧错误。
6. **补充低频内容。** 社区插画为原创 CSS 几何图形，放在服务目录之后；公告展开实际文字，FAQ解释概念与隐私边界。
7. **验证窄屏与键盘。** 390px 两列服务卡、320px 一列；手机表单改成单列，保持正文可读性。

## 日期与提交逻辑

`cityToday()` 使用 `Intl.DateTimeFormat(..., { timeZone: 'Asia/Shanghai' }).formatToParts()` 组合 `YYYY-MM-DD`。即使浏览器位于洛杉矶，表单仍按 UTC+8 城市服务时间判断今天，不使用 UTC 的 `toISOString().slice(0, 10)`。

原生 date input 的 `required/min` 提供第一层校验；提交函数再次检查日期格式和下界。表单顶部明确“所有字段均为必填”，同时说明使用示例资料。提交函数还检查称呼不只是空格、示例邮箱非空、演示确认已勾选，以及时段属于允许列表。

没有真实后台、席位、证件核验或政务办理。当前日期校验保证演示一致性，不能替代上线服务中的服务器校验。表单不支持实际过期席位或工作日安排，因此没有宣称任何真实可预约性。

## 焦点与数据

- 搜索按钮：滚动到服务目录并使目录区域获得焦点。
- 清除搜索：输入框重新获得焦点；无结果后的“查看全部服务”恢复目录焦点，避免按钮消失后焦点落回文档。
- 服务卡片：预选对应服务并聚焦服务 select。
- 提交错误：聚焦带 `role="alert"` 的错误摘要；日期错误也标注 `aria-invalid`。
- 提交成功：聚焦“本地预约摘要”区域。
- 重新安排：清除结果并聚焦新表单的服务 select。
- 手机导航：Escape 关闭并返回菜单按钮；点击导航后收起。
- 预约信息不写本地存储，不发送网络请求；刷新后清除。示例邮箱不会出现在摘要里。

在开发服务器运行时，从仓库根目录执行：

```bash
node apps/civic/verify.mjs
# 也可对已启动的独立构建预览检查：
PREVIEW_URL=http://127.0.0.1:4173/civic/ node apps/civic/verify.mjs
```
