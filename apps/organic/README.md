# MORI 森间：植物与生活品牌独立站复刻指南

用植物、陶器和柔和留白表达慢生活，再把浏览、商品详情、购物袋与订单摘要串成完整任务。本套是独立站点，拥有自己的导航、品牌故事、养护内容和页脚，不使用统一展示框架。

## 运行、构建与目录

从仓库根目录使用已验证的 Node.js 24 环境：

```bash
cd /workspace/GptTest
npm ci
npm run dev -- --mode organic
```

默认开发端口 `5179`；可追加 `--port 5279`。项目依赖与锁文件都在仓库根。

```bash
npm run typecheck
npm run build -- --mode organic
npm run preview
```

产物为 `dist/organic/`，根预览访问 `/organic/`。类型检查会覆盖仓库全部站点。

- [index.html](index.html)：中文页面、标题、元信息和根节点。
- [src/main.tsx](src/main.tsx)：`products`、`Botanical`、`Dialog`、`App`；所有商品与交互可在这里定位。
- [src/styles.css](src/styles.css)：站内全部视觉与响应式，未引用其他站点 CSS。
- [BATCH-01.md](../../docs/reviews/BATCH-01.md)：购物袋运费、移动布局等实测记录。

## 页面骨架与搭建顺序

1. 写公告条、`mori` 字标、主导航和购物袋按钮；数量从状态计算，初始为 `00`。
2. 建双栏 `.hero`：左侧两行中文、说明和主行动，右侧渐变拱形底、斜向窗光、植物、印章、标本说明。三枚编号按钮切换橡皮树、龟背竹、琴叶榕；名称、价格与可打开的商品详情同步。
3. 放价值说明横条，再建商品区：分类、结果数与原生价格排序 → 商品网格 → 演示说明。每张商品卡按完整标本、商品名/价格、拉丁名、用途、整行加入按钮的顺序呈现。
4. 用深绿色 `.story` 打断浅色节奏；左侧植物线描，右侧品牌观点与签名。
5. 补三条养护建议、原生 details FAQ、来信表单、页脚，再接商品详情和购物袋窗口。

主要断点为 1000px 与 700px。700px 以下首屏上下堆叠，商品保留两列，故事和养护变单列；350px 以下标题与商品名换行规则单独适配。手机原生输入框、排序选择框为 16px；操作按钮至少 44px 高，数量加减为 44×44px。购物袋最大宽度不超过屏幕。手机不靠整体缩小页面实现适配。

## 植物和器物：从 SVG 规则复刻

`Botanical({ variant, id, hero })` 使用 `500×590` 坐标。它是全部商品图与首屏图的共同绘图函数，但不承载业务状态。

- 先画底部虚化椭圆阴影，再画器物或植物，保持所有产品落在同一地平线上。
- 植物盆用梯形路径和顶部椭圆叠出厚度；陶土 `linearGradient` 从深棕到浅粉再回深棕。
- 叶子用 `{x,y,r,s}` 参数做平移、旋转、缩放；橡皮树使用六片，龟背竹与琴叶榕各五片独立位置与尺寸，构成不同的舒展/直立轮廓。叶片、叶脉与主干分层，而不是复制整张图片。
- `variant=1/3/5` 分别采用完整叶、开裂叶和波状叶路径；`2/4/6` 是陶瓶、台灯和水壶。
- `id` 前缀区分 `hero`、`product-1`、`detail`、`bag-1` 等实例，让渐变与滤镜引用不冲突。

```css
.arch-bg {
  background: linear-gradient(140deg, #e8e9dc 4%, #dce1cc 65%, #d4dcc5);
  border-radius: 250px 250px 5px 5px;
}
.round-stamp {
  transform: rotate(-15deg);
}
```

首屏图轻微旋转 `-2deg`，印章形成相反尺度的视觉锚点。商品图不再使用超出容器的负边距放大：图框为桌面 365px / 手机 210px / 320px 窄屏 185px，SVG 以 100% 宽高适配，保留盆底与顶叶。商品 hover 轻微缩放；减少动态效果模式会去掉这些变换。
故事区线描也由 SVG 叶片重复生成，与商品图共享植物语汇，但改用细描边而非立体填色。

## 业务状态与关键定位

| 状态/函数                | 用途                                    | 约束                                                   |
| ------------------------ | --------------------------------------- | ------------------------------------------------------ |
| `products`               | 六商品的 ID、类别、价格、插画、养护说明 | `plants` 与 `objects` 各三件                           |
| `category`               | 全部/植物/器物筛选                      | 对真实数组过滤；按钮 `aria-pressed` 同步               |
| `specimen` / `sort`      | 首屏标本与价格排序                      | 复用商品数组；排序不改变购物袋或原始数组               |
| `selected`               | 商品详情                                | 空值关闭；内容来自同一个商品对象                       |
| `bag` / `add` / `change` | 购物袋与数量                            | `mori-bag` 本地持久化；每件 1–99，减为 0 删除          |
| `count` / `total`        | 件数与商品合计                          | 从 `bag` 和价格派生，不建立独立金额状态                |
| `cartOpen` / `order`     | 抽屉与摘要                              | 修改数量后清除旧摘要状态                               |
| `message`                | 添加成功提示与查看购物袋入口            | `role=status`，2.5 秒后自动清除                        |
| `storageUnavailable`     | 持久化异常反馈                          | 写入失败时购物袋内显示仅当前页面保留；会话操作仍然可用 |
| `subscribed`             | 来信意向反馈                            | 当前页面内显示成功；不发送邮件、不持久保存邮箱         |

读取 `mori-bag` 时先验证对象类型、真实商品 ID、整数与数量范围；存储异常退回空袋。写入失败时页面内体验仍可继续，并在购物袋标题下显示“浏览器未允许保存，购物袋仅在当前页面保留。”；成功写入后清除此状态。不要把 `catch` 静默吞掉后仍承诺刷新保存。
运费规则：商品合计满 `299` 为 `0`，否则 `18`。`remainingForShipping = max(0, 299 - total)` 与进度条仅由合计派生；摘要显示总计，但不付款、不生成服务器订单。

手机购物袋底栏只在 `count > 0 && !cartOpen && !selected` 时显示，数量、商品合计从已有状态派生。底栏按钮打开同一个购物袋；商品详情加入后也有直接查看入口。CSS 底栏与抽屉底部考虑 `env(safe-area-inset-bottom)`；`body:has(.mobile-bag-dock) footer` 为底栏留出底部空间，避免末尾内容被遮住。没有新增购物袋副本或额外数量状态。
`Dialog` 自行实现名称、Esc、Tab 循环、背景滚动锁定和焦点返回；商品弹窗与购物袋共用这个站内组件。关闭后在下一帧确认没有其他弹窗，再恢复仍连接的原触发按钮；手机底栏在弹窗期间被卸载时，改为聚焦重新出现的底栏按钮，退路为稳定的顶部购物袋入口。用 `preventScroll` 保留浏览位置。

## 验收步骤

1. 在 1440px 查看三列商品与双栏首屏；390px、320px 查看完整商品图、两列商品、单列故事和导航菜单，无横向滚动。检查三枚首屏编号是否真正切换植物与价格。
2. 点“有生命的绿”应剩三件；器物也应三件。全部商品按价格升序应为 128、158、168、198、238、268。打开橡皮树详情，标题、说明、价格 `¥168` 与卡片一致。
3. 加入一件橡皮树，手机出现底栏；详情与抽屉打开时底栏消失。刷新后袋中仍一件；总计 `168+18=186`，距包邮 `131`。增至两件后达到包邮，总计 `336`。橡皮树加陶器则为 `296+18=314`。
4. 生成摘要应明确“未创建真实订单”；再修改数量应回到可生成摘要状态。减到零后显示空袋提示。
5. 用 Tab/Shift+Tab 遍历窗口，禁用的 99 件加号不进入循环；Escape 关闭并返回原按钮。详情“查看购物袋”只保留一个弹窗；手机导航选项点击后收起，FAQ 可展开，订阅仅显示本地反馈。
6. 将 `mori-bag` 写为 `null`、`[]`、非法 JSON 或包含未知 ID、负数、小数、字符串、100 的对象，刷新应恢复空袋；有效数量与无效数量混合时只保留有效项。
7. 用浏览器初始化脚本将 `Storage.prototype.setItem` 改为抛出 `SecurityError`，加入商品后购物袋必须显示无法保存提示；加减与摘要仍能操作，刷新后不可声称已保存。
8. 手机添加商品后滚动到页脚，末尾链接须在固定底栏上方；开启减少动态效果，商品 hover 不缩放、锚点不平滑滚动。

本轮前后截图与自动验证结果保存在 [`artifacts/optimization/`](../../artifacts/optimization/)：`organic-{320,390,1440}-before/after.png`、商品区与购物袋局部图、`organic-storage-denied.png`、`organic-results.json`（本轮 18 组通过）。预览运行后可执行 `node artifacts/optimization/organic-check.mjs` 重验。截图验证包含 Chromium 桌面与移动尺寸，不等同于真机 Safari 安全区域测试。

## 独立部署和后续接入

将 `dist/organic/` 的内容复制到静态站根目录即可。相对 `base:'./'` 支持静态子目录；保留 `assets/` 相对位置。无需其他样例、目录站或后端服务一起运行。

如果另建仓库，应补齐 React、React DOM、lucide-react、Vite、TypeScript 和自己的锁文件；当前 `apps/organic/` 共用仓库根构建配置。
购物袋只在同一浏览器同一站点源下持久保存；换设备不会同步。商品、价格、包邮和订阅均用于演示，真实商城需要库存、订单、支付和服务端金额校验。
