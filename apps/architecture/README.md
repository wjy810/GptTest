# STILL — 建筑与空间网站复刻手册

STILL 是完整、独立的建筑事务所界面习作。首屏由全幅原创 SVG 建筑景观主导，文字压低在画面底部；作品以错落画廊呈现。所有项目、地点组合、面积和材料均为虚构概念叙事，不代表实际建成作品或施工建议。

## 1. 独立启动与构建

从仓库根 `/workspace/GptTest` 执行：

```bash
npm ci
npm run dev -- --mode architecture
```

当前开发端口为 **5185**（`5173 + sites.json` 中的索引）。开发服务持续运行；在另一个终端执行检查与构建：

```bash
npm run typecheck
npm run build -- --mode architecture
python -m http.server 4185 --directory dist/architecture --bind 0.0.0.0
```

产物目录 `dist/architecture/` 可以单独部署。`base: './'` 让资源路径相对于页面，不依赖目录页或其他样例。本站不请求远程字体、图库或后端。

## 2. 结构与设计重心

| 区域         | 选择器 / 组件                      | 设计意图                                         |
| ------------ | ---------------------------------- | ------------------------------------------------ |
| 极细导航     | `.header`                          | 保持品牌、章节和联系入口，避免工具栏抢占建筑画面 |
| 全幅建筑首屏 | `.hero-image`、`ArchitectureScene` | 建筑先于文案；侧边竖排标签与底部小标题建立画册感 |
| 项目信息栏   | `.hero-information`                | 编号、名称、地点、年份和切换动作放到图像下方     |
| 方法陈述     | `.intro`                           | 以大留白和少量正文建立阅读节奏                   |
| 作品画廊     | `.project-gallery`                 | 不等宽两列、错位高度、无卡片外框；强调图像和编号 |
| 事务所与原则 | `.practice`、`.principles`         | 从空间画面转向设计方法与材料观念                 |
| 观察笔记     | `.notes`                           | 原生 details 按需展开，减少页面噪声              |
| 项目简报     | `.contact`                         | 将抽象合作意向变成可下载、可编辑的具体信息       |
| 巨型页脚     | `.footer-word`                     | 用一条完整的品牌字标结束阅读                     |

与常见“左侧营销标题 + 右侧卡片”不同，首屏是一个完整空间。标题和动作附着于景观边缘，布局的主角始终是建筑。

## 4. 原创建筑 SVG 的构造

所有建筑由 `ArchitectureScene({ scene })` 渲染，使用固定 `viewBox="0 0 1600 900"`。它是二维建筑空间插画，不是 3D 模型、照片或 CAD 图。

### 统一的空间底层

1. 天空使用垂直线性渐变，从冷灰过渡到暖灰。
2. 远景用两组低透明度山形路径建立前后距离。
3. 地面使用从深到浅的渐变，避免完全平涂。
4. 建筑按远到近的顺序叠放多边形：侧体量 → 屋面 → 侧墙 → 正立面 → 窗 → 地面构件。
5. 屋面通常更亮，侧墙更暗，正立面使用缓慢的渐变；先靠明度建立体积，再补材料线。
6. `feTurbulence`、低透明度 alpha 与 multiply 混合添加微弱颗粒。最后叠一层低透明暖色，让各部分共享环境色。

### 每个场景的差异

| `scene`     | 几何元素                                 | 主要表达               |
| ----------- | ---------------------------------------- | ---------------------- |
| `courtyard` | 错动盒子、深檐、通长玻璃、池水、台阶、树 | 生活围绕庭院与光线展开 |
| `gallery`   | 低长体量、连续木格栅、抬高天窗、人物尺度 | 重复结构与观看路径     |
| `coast`     | 面海低体量、水平海面、岩石、厚墙         | 地形、庇护与远方视线   |
| `pavilion`  | 开放大屋顶、重复梁柱、夯土体量、长凳     | 屋檐下的共享生活       |

玻璃面不直接填纯黑，而是用灰绿渐变，再叠室内暖色块、家具和竖向窗框。水面用低对比平行线表达反光。人物保持极简轮廓，只用于建立尺度。

每个 SVG 实例通过 `useId()` 生成独立的渐变 / filter ID。页面同时出现首屏、画廊、事务所配图和弹窗，如果写死 `id="sky"` 等名称，会造成多实例引用碰撞。

### 图像裁切

`preserveAspectRatio="xMidYMid slice"` 保持建筑比例并裁切边缘。手机首屏将 SVG 宽度设为容器的 200%、向左平移 50%，形成近景；画廊约为 140%，保留更多完整体量。不同画面不是把整个桌面截图缩小。

复刻时要逐个检查四种场景在首屏、缩略图与弹窗中的裁切。不要只看第一幅。

## 5. 首屏与画廊的空间关系

### 首屏

- 景观铺满容器，标题放在左下，按钮放在右下。
- `.hero-image:after` 在画面下半部叠透明到 `#243025a6` 的渐变，让白色标题和操作按钮有稳定对比。
- 侧边 `.hero-vertical` 使用 `writing-mode: vertical-rl`，只承载系列编号。
- 项目信息不挤进图像，放到独立的 71px 信息栏。

### 画廊

- 桌面列比例 `1.25fr 1fr`，间距 `75px 55px`。
- 偶数项目向下错位 125px，图片较矮，形成编辑式节奏。
- 图片外没有圆角卡片、阴影或填充面，只有画面与下方细线。
- 标题、中文名、类型、地点和年份形成可扫描的固定位置。
- 480px 以下改成单列并取消错位，图片保持约 300px 高。

`.project-image` 悬停仅缓慢放大到 `1.035`，不会改变页面布局。系统减少动态效果设置会禁用该过渡。

## 6. 交互与状态

### 项目数据

`projects` 中每项包含：

```ts
{
  id: string
  title: string
  cn: string
  place: string
  year: string
  category: string
  scene: 'courtyard' | 'gallery' | 'coast' | 'pavilion'
  area: string
  material: string
  text: string
  idea: string
}
```

名称、图像、画廊、详情都来自同一条数据，避免切图后项目信息没有同步。

### 首屏切换

`hero` 是项目索引，`active = projects[hero]`。左右按钮使用 `(hero + 3) % 4` 和 `(hero + 1) % 4` 环绕切换。切换后同时更新景观、编号、名称、地点、年份及打开详情的目标。

### 项目筛选

`filter` 默认 `全部`，直接筛选 `projects`。现有类别数量为：居住 2、文化 1、公共 1。按钮通过 `aria-pressed` 表达选中状态；数量由数据计算。

### 原生项目详情

`project` 是当前项目或 null。effect 根据它调用 `<dialog>` 的 `showModal()` / `close()` 并锁定背景滚动；`aria-labelledby="dialog-title"` 关联标题。显式 Tab / Shift+Tab 保持首末焦点循环，关闭按钮、Escape 与真正位于窗口边界外的点击都更新状态。详情中的“开始你的空间简报”将焦点交给表单的项目方向 select。

项目场景使用 `project-scene-*` 类名前缀，避免 `scene="gallery"` 时与外层 `.project-gallery` 网格同名；同名曾导致第二张作品在桌面被嵌套成另一层两列网格。

详情包含放大图、事实列表、设计叙事、材料与“虚构概念”说明，并可跳转到简报表单。

### 观察笔记

采用原生 `<details><summary>`，无需额外 React 状态。Enter 或空格均可展开。每条笔记都有独立标题，正文在需要时出现。

## 7. 本地简报生成

表单维护 `service`、`size`、`location`、`idea` 四项状态：

- 项目方向：住宅 / 文化 / 社区公共 / 其他研究。
- 面积：五个范围，包含“尚未确定”。
- 地点：必填，最多 120 字符。
- 空间想法：必填，8–2500 字符。

`downloadBrief()` 先阻止表单默认提交，然后拼接 Markdown、创建 Blob 和对象 URL，通过下载链接生成 `still-project-brief.md`。对象 URL 在 1 秒后撤销。

示例文件内容：

```md
# STILL / 项目初步简报

生成日期：2026-11-17

项目方向：文化与艺术空间
预估面积：300–1000 m²
项目地点：杭州

## 关于空间的想法

希望创造一个可以阅读和举办小型展览的社区空间。
```

真实文件还包含“本地生成、没有发送、项目为虚构概念”的说明。生成日期使用浏览器运行时的 UTC 日期。提交前对地点和想法执行 trim 校验：地点不得为空白，想法除首尾空白后至少 8 个字符；错误摘要获得焦点，输入修改后清除。下载成功后显示状态提示；修改任一字段会清除旧提示。本站不发送邮件、创建订单或保存表单到服务器。

## 8. 推荐复刻步骤

1. 先搭建导航、全幅景观容器、下方信息栏与页面章节。
2. 用三个纯色多边形画出第一栋建筑：屋面、侧墙、正立面。先保证透视关系读得懂。
3. 逐层增加玻璃、窗框、阴影、地面、水面、人物或植物，避免一次堆满细节。
4. 把图像封装成带 `scene` 参数的组件，用独立 SVG ID 避免多实例冲突。
5. 加入作品数据与画廊，校准桌面错位及手机单列节奏。
6. 加入筛选、首屏切换和原生详情弹窗，再检查数据是否一致。
7. 实现简报生成并读回下载内容，不能只验证出现了“成功”提示。
8. 校准正文对比、焦点、键盘和减少动态效果。
9. 分别验收四个场景在桌面、手机与弹窗中的裁切后，再增加项目。

## 9. 验收清单及现有证据

1. 1440px 与 390px 浏览完整页面：首屏建筑比例正常，标题完整，页面无横向滚动。
2. 通过首屏左右按钮循环四项：图片、编号、名称、地点一致，打开的是当前项。
3. 点击居住 / 公共筛选，分别出现 2 / 1 个项目；恢复全部为 4 个。
4. 键盘聚焦作品图，Enter 打开详情；标题、面积、材料正确；Escape 关闭。
5. 键盘聚焦笔记 summary，Enter 展开正文。
6. 填写项目方向、面积、地点和想法，下载 Markdown 并读回所有字段。
7. 手机上展开导航，点击作品锚点后导航关闭。
8. Tab 的第一步显示“跳到主要内容”，所有主要控件都有明显焦点。
9. 系统减少动态效果下，页面没有强制动画；图片放大过渡与平滑滚动关闭。
