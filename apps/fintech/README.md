# MONO — 金融数据工作台

以数据工作区为首页的独立网站：桌面侧栏、紧凑工具栏、资产摘要、组合曲线、分类表格和规划计算。墨黑背景提供分层，薄荷色用于组合数据，紫色用于基准与规划，不依赖营销首屏或目录站外框。

所有资产名称、价格和组合数值都是本地虚构样本。这里没有登录、账户连接、实时行情、交易或实际理财服务。

## 运行与构建

从仓库根目录执行：

```bash
npm ci
npm run dev -- --mode fintech
npm run build -- --mode fintech
npm run typecheck
```

开发默认端口为 5182，独立构建输出为 `dist/fintech/`。`index.html`、`src/main.tsx` 和 `src/styles.css` 共同构成该站；仅使用工作区中的 React、React DOM 和 lucide-react 依赖。

## 复刻步骤

### 1. 先建信息结构

将最常读的数据放在顶部摘要，将趋势与分布作为第二层，将可检索明细放在第三层。所有更改都在当前工作区生效。这里没有“点击后没有反应”的买入按钮，操作围绕观察、筛选、导出与理解展开。

### 2. 定义三个层级的视觉角色

- 页面底色 `#111214`，面板 `#191a1e`，悬停或工具表面 `#202126`。
- `--mint` 标识我的组合；`--purple` 标识模拟基准及规划。负向变化另用淡红并显示负号/方向箭头，不能只依赖颜色。
- 灰色边框分隔区块，数字使用 tabular-nums 或等宽数字布局；价格对齐右侧，名字对齐左侧。
- 圆角和阴影克制，依靠内容密度、局部高亮和大数字建立层级。

### 3. 自己实现可解释的 SVG 曲线

`AssetChart` 将每条 ISO 日期转换为时间戳：

```text
x = 左边距 + (当前时间 − 起始时间) ÷ (结束时间 − 起始时间) × 绘图区宽度
y = 绘图区底部 − (当前值 − 数值下限) ÷ (数值上限 − 数值下限) × 绘图区高度
```

因此不等间隔日期不会被错误画成等距离。曲线、区域填充、网格、轴标签和可选基准是独立 SVG 图层。鼠标悬停按最近横坐标寻找采样点；普通用户和辅助技术都可以展开数据表直接读取日期与金额。

桌面使用 `760 × 250` 的 viewBox，手机切换为 `380 × 250` 并重新计算绘图区宽度。这样不会把桌面坐标和文字整体缩成不可读的小图。

这条示例折线的纵轴没有从零开始，用于观察期间变化；刻度在图中明确给出，精确数据在表格中。它不是实时行情或收益率统计模型。

### 4. 让摘要与下载共享数据

期末组合总值等于该周期最后一条；周期变动等于期末减期初；变动百分比等于差额除以期初。CSV 使用当前周期的全部日期、组合值与基准值，保留两位小数。文件名包含周期，并且导出 Blob URL 用完后释放。

基准开关只控制图中的比较线；原始数据表和 CSV 仍保留基准列，避免误以为隐藏图层删除了数据。

### 5. 实现有恢复路径的观察列表

初次打开显示两个示例关注项。持久化只存资产代码，不存个人信息或账户数据。

- 初始化对读取内容做类型检查、已知符号筛选与去重。
- 类别为“我的关注”时，将关注列表作为筛选条件。
- 用户主动清空时保存空数组；不要删除存储键再让默认项复活。
- 存储被禁用或配额失败时，当前页操作仍成立，但状态提示明确说明未能持久保存；清空失败也不会伪报持久数据已删除。

### 6. 让计算器可以手动复算

该计算器假设每月末投入相同金额，采用名义年率除以 12 得到月率：

```text
p = 每月投入金额
r = 假设名义年率 / 100 / 12
n = 年数 × 12
投入总额 = p × n
终值 = r 为 0 ? p × n : p × ((1 + r)^n − 1) / r
假设变化 = 终值 − 投入总额
```

允许的参数：投入 100–3,000 USD（步长 50），时间 1–30 年，假设年率 −2%、0%、4%、8%。负增长时使用“假设减少”，显示负方向差额。未模拟税费、手续费、通胀和真实波动。

例如每月末投入 500 USD、10 年、假设年率 4% 时，计算结果四舍五入约为 **73,625 USD**，累计投入 **60,000 USD**。零增长时应严格等于累计投入。

“标记参数”只是当前页面内存标记；修改任一参数后标记自动取消，不暗示已经创建实际投资计划。

### 7. 做真实响应式和输入方式检查

- 桌面数据表列对齐；手机在具名、可聚焦的表格容器内横向浏览，不让整页溢出；提供触摸/方向键提示，Tab 聚焦容器后可用左右方向键滚动。
- 手机导航展开后焦点进入首条链接；Esc 关闭并返回菜单按钮，选中章节后收起并聚焦目标区。通知面板打开时聚焦关闭按钮，关闭或 Esc 后返回铃铛。
- 清除搜索后焦点回到输入框；无结果重置后焦点落在市场观察区，不会因为按钮消失而丢失到页面主体。
- 所有图标按钮有可访问名称，范围按钮有 aria-pressed，结果表有列标题。
- reduced-motion 时关闭平滑滚动与过渡。
- 低视力或无法分辨颜色时，仍能通过数字、方向、表格和文字理解数据。

## 2026-11-17 手机阅读与触控优化

本轮只调整 `styles.css`，保持原数据、计算公式、CSV、关注持久化与事件处理不变。桌面侧栏、四张摘要卡、曲线与配置并排、全宽资产表仍是主要结构。

- 手机关注、图标、清除、周期按钮的点击区至少44×44；时间范围独占一行，表格单元格适当减小上下内边距，避免扩大星标按钮后每行过高。
- 手机搜索与增长率选择框为16px字号、44px高。假设标签与选择框上下排列；两个滑块保留并排布局，用44px高的输入区域承载3px细轨道，兼顾手指操作和原有数据密度。
- 数据来源、模拟边界与公式说明手机使用12px、桌面使用11px；手机配置金额为11px并移到类别下方，摘要说明为11px。表格仍在具名局部容器中横向浏览。
- 手机SVG坐标文字扩大后，最初的320px截图出现末端日期靠得过近。最终CSS保留首枚、第三枚与末枚已有日期刻度，显示位置仍来自真实日期坐标；其余样本与日期完整保留在底表和CSV。对四周期逐一测量，320px相邻可见日期最小间距约19px，390px约24px。
- `text-wrap: balance`用于窄屏开头说明，避免仅剩一两个汉字落在第二行。没有新增页面区块或业务功能。

实际完成独立生产构建、TypeScript检查，以及本机Chromium的12组针对性验证：1440/390/320页面及面板边界；手机主要触控区和输入字号；四周期日期文字边界；实际1W CSV下载与底表逐项匹配；搜索、关注、清除后的焦点；滑块键盘增量、零增长与逐月台账复算；当前页参数标记；运行异常检查。另实看三尺寸最终截图。实体iOS设备不在本轮验证范围。
