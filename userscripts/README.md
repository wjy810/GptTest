# Claude 会话守护（用户脚本）

`claude-session-guard.user.js`：只保留本浏览器当前会话和你勾选的会话，其余自动踢掉。脚本走 claude.ai 网页原生的活动会话接口。

## 这次修的问题：踢完之后有残留（Claude Code · 未知 · 未知）

| 版本 | 原因 | 修法 |
| --- | --- | --- |
| 4.0.1 | 先发不带应用的 `{session_uuid}`，接口一回 200 就当成“确认格式”。踢 Claude Code、桌面端、iOS 会话时，服务端可能按网页端处理：返回成功，会话却没踢掉。之后脚本只会反复发同一种格式。 | 带 `application_slug` 的格式优先。每次返回成功都重读列表，会话真的消失了才记住格式；“返回成功但还在”就在同一轮立刻换下一种。格式按应用分别记。 |
| 4.0.2 | Claude Code 会话的 `created_at` 是 null（网页上显示“未知”）。v4.0.0 定位会话只认 `session_uuid` 或 `created_at`，两样都没有就标成“无法识别 · 不处理”，日志还照写“干净了”。 | 先用其它 id 字段；都没有就按“应用 + 客户端”给一个稳定标识，再照网页那一行的样子发 `{created_at: null, application_slug}`。同应用里有本机或保留的会话时不发这种请求。 |
| 4.1.0 | 真实接口可能要别的格式，甚至是另一个接口，脚本猜不到。 | 在 设置 → 账户 手动点一次那条会话的「终止」，脚本只观察网页自己发出的请求并照着学。以后同一应用的会话照这个格式踢，照样确认会话真的消失。 |
| 4.1.1 | 脚本在后台踢掉会话后，设置页自己的表格不一定会刷新，踢掉的行会一直挂着。 | 踢掉后提醒网页重新拉取一次。面板提示以面板列表为准，并提供「刷新本页」按钮。顺带修了手机上面板左边被裁掉的问题。 |
| 4.1.2 | 自查。 | 学习只观察“终止 / 撤销”类请求；`null` 请求的安全规则更保守；同组计数按实际条数算。 |

## 之后的优化

| 版本 | 内容 |
| --- | --- |
| 4.1.3 | 标签页在后台放久了，Chrome 会把定时器压到约 1 分钟一次。现在由一个小 Worker 按时叫醒检测；网页不允许建 Worker 时，自动退回普通定时器。 |
| 4.2.0 | 新登录的会话先踢。待踢的比设定条数多时自动加快，每轮最多踢 5 条，但要先确认踢掉过一条才加快，而且每条都照样自检。一轮踢完还有待踢的，0.5 秒后就接着下一轮。 |

## 在真实浏览器里验证

1. 在 Tampermonkey 或 Violentmonkey 里用本文件替换旧脚本，然后刷新所有已打开的 claude.ai 标签页。
2. 打开面板，在“会话”列表里找到 Claude Code 那一行，标签应显示「会被踢出」，不再是「无法识别 · 不处理」。建议先开「预演」跑一轮，日志里应出现「预演：本来会踢「…」」。
3. 关掉预演，启动守护，然后看日志：
   - 出现 `🧠 踢人请求格式确认（claude-code）：…` 和 `🦶 已踢：…`，就说明踢掉了。刷新设置页确认那一行消失。
   - 出现 `❌ 踢不掉…`，就在 设置 → 账户 里手动点一次那一行的「终止」。日志应出现 `🧠 学到网页自己的「终止」请求（claude-code）：…`，之后新的 Claude Code 会话会被自动踢掉。
4. 如果还有残留，在面板里点「导出日志」，把以 `🔍` 开头的几行发给我。这几行里只有字段名、类型、应用名和客户端名，没有会话 id。

## 本地测试（模拟接口，不连 claude.ai）

```bash
node userscripts/test/session-guard.test.mjs
```

测试用 Playwright 打开一个假的 claude.ai 页面，注入 GM_* 垫片和脚本，再由模拟服务器按各种场景回应。`CSG_SCRIPT=路径` 可以换成要测的其它版本：原版 v4.0.0 在这套测试里会留下 Claude Code 残留。`test/screens.mjs` 用来截面板图，截图在 `test/screens/`。

说明：模拟接口的行为是按脚本原注释和截图推断的，并非 claude.ai 的真实接口。真实接口要以上面第 3 步的日志为准。
