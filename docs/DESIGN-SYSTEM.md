# 设计系统与 UX 实施约定

本文件解释十二个独立网站的设计决策，并给后续扩展提供基线。各站的具体实现以 `apps/<站点名>/src/main.tsx` 和 `apps/<站点名>/src/styles.css` 为准；下列 token 是资料目录和复刻练习可采用的建议值，不是所有网站必须共用的主题，也不代表外部案例的原始参数。

## 视觉方向

资料目录可以采用米白画布、近黑文字与橙红强调，类似设计档案与独立杂志。十二个网站分别拥有独立品牌、导航、信息结构与视觉系统，不能被目录页的公共外壳包住。

目录与网站的职责不同：目录帮助发现与查阅来源；独立网站承担各自的真实本地用户任务。它们共享的是 HTML 语义、键盘可操作性、状态真实性等质量底线，不是统一的页面模板。

## 排版与布局

- **标题：** 主视觉允许夸张比例，中文长标题用 `clamp()` 和自然换行；避免固定高度裁掉字形。
- **正文：** 基线 16px、行高 1.6–1.8；每段保持一个主题。介绍性文字不能只剩英文装饰标签。
- **辅助信息：** 分类、编号与日期可用等宽字体，字号建议不小于 12px。
- **容器：** 主内容居中并设最大宽度，边距随视口缩放；卡片网格使用 `minmax(0, 1fr)` 防止长文字撑破布局。
- **断点：** 从内容需要出发。窄屏单列，中等视口两列，宽屏三列；不要以具体手机型号作为设计逻辑。
- **层级：** 先页面标题、再工具栏、再结果，再辅助说明。同屏只设一个最强的主操作。

### 从实际优化中提炼的检查方法

- **可编辑文字和装饰标签分开处理。** 手机 input、select、textarea 使用至少 16px 的文字；缩小控件文字会损害编辑体验，也可能触发 iOS 的聚焦缩放。当前验证基于 Chromium 的实际计算字号，不等同于 Safari 真机验证。
- **放大触控区时同时重排邻居。** 主要独立按钮以 44px 操作区为目标；图标不必一起放大。按钮扩大后重新检查标题、数字和卡片边界，不能靠覆盖其他内容获取点击面积。
- **整页不溢出不代表内部内容完整。** 测量海报标题、说明和插画相对容器的位置；`overflow: hidden` 可以遮住真实缺陷。ODD 的标题计数则应直接修复字号或布局，不能用全页裁切隐藏溢出。
- **页面变短不是唯一目标。** 目录单列卡片和清楚的日程会增加手机滚动长度。记录阅读宽度、重要任务位置与入口可达性，再判断取舍；不要通过缩小实质正文制造“更紧凑”。
- **动态卸载的触发器需要替代焦点目标。** 打开购物袋会卸载浮条，关闭时旧 DOM 引用已经失效；应定位重新出现的按钮或稳定入口，并保持滚动位置。
- **按需加载必须保留失败路径。** 资料阅读器延迟加载能够减少首屏脚本；下载原文和关闭面板仍应在加载失败时可用。提示必须说明实际可做的恢复动作。

## 组件及状态契约

下表按站内实际存在的功能使用，并非要求每个独立站点都增加搜索、收藏或参数控件。目录站的检索与来源状态不能替代各网站自己的主要任务。

| 组件               | 必须处理的状态                                       | 实施约定                                                   |
| ------------------ | ---------------------------------------------------- | ---------------------------------------------------------- |
| 搜索框             | 空输入、有输入、无结果、清空                         | 有可见或程序化标签；清空后保留焦点；结果数量与实际内容同步 |
| 风格筛选           | 默认、选中、不可用                                   | 用 `aria-pressed` 或合适的单选语义；状态不只靠颜色         |
| 收藏按钮           | 未收藏、已收藏、空集合；启用持久化时再处理存储不可用 | 明确生命周期和添加/取消动作；错误时不要宣称持久化成功      |
| 案例卡片           | 默认、hover、focus、选中                             | 使用真正的链接或按钮；嵌套收藏按钮时避免嵌套交互元素       |
| 来源条目           | 已读取、受阻、仅供参考                               | 状态与证据紧邻；“可打开”不等于“设计已完整分析”             |
| 详情面板           | 打开、内部滚动、关闭                                 | 可见关闭按钮、Escape、焦点进入与恢复                       |
| 参数滑条（使用时） | 最小值、最大值、键盘调整                             | 展示标签和当前值；数值必须影响预览                         |
| 复制按钮（使用时） | 默认、成功、失败                                     | 成功提示只在写入成功后出现；失败允许手动选中文本           |

### 搜索与筛选

搜索应优先匹配标题、风格、标签和说明，不要求用户知道作者内部的分类名称。搜索与风格筛选叠加时采用 AND 逻辑；需要在界面中展示当前条件，并提供重置。

无结果不是错误：显示当前关键词、提供清空搜索或切换“全部”的操作。不要填充不相关内容伪装成搜索成功。

### 收藏与本地存储

先确定收藏的生命周期，再设计反馈。当前 **AURA 的收藏只存在 React 页面状态中，刷新即重置**；**FOLIO 的 `folio-saved` 使用浏览器 localStorage，刷新可恢复**。MORI 的 `mori-bag` 是持久购物袋，不应在文档中称为收藏。以上都没有云同步。

对于声明持久化的功能，用稳定的内容 ID 存储集合，不把整份卡片对象持久化，以便以后修正文案而不丢失收藏。读取时对 JSON 解析失败、过期数据和未知 ID 做容错；写入失败时保留当前会话操作，同时提示无法保存到后续访问。FOLIO 与 MORI 现已提供可见的写入失败反馈，并用浏览器实际拒绝 Storage 写入验证了当前页面可继续使用、刷新不能恢复未保存内容的边界。不要为修复解析问题而擅自清理其他功能的存储键。

### 来源状态

来源数据见 [`sources.json`](../src/data/sources.json)。推荐状态含义：

- `verified`：本轮已获取并阅读可识别的内容；证据必须说明读取范围。
- `blocked`：本轮请求受网络、登录、反爬或其他条件限制；记录实际错误，不猜测原因。
- `reference`：已知的参考入口，但本轮未实查具体内容。

“页面请求成功”“阅读文档”“检查视觉”“观看视频片段”是不同证据级别。不要在 UI 中把它们合并为“已验证全部内容”。

## 六种基础视觉语言的变量边界

| 风格      | 最重要的识别特征       | 可以调整                 | 不应牺牲                 |
| --------- | ---------------------- | ------------------------ | ------------------------ |
| Editorial | 大标题、留白、图注     | 字体、标题比例、图文位置 | 阅读顺序与正文行高       |
| Brutalist | 粗边框、硬阴影、高对比 | 强调色、阴影偏移         | 控件可识别性             |
| Swiss     | 网格、对齐、编号       | 列宽、留白、类型尺度     | 信息关系                 |
| Glass     | 半透明层、景深         | 模糊、背景色、圆角       | 真实背景下的可读性       |
| Terminal  | 等宽字、日志、深底     | 色调、密度、扫描线       | 状态真实性与信息可复制性 |
| Organic   | 柔和色、圆角、自然形态 | 间距、圆角、装饰         | 点击边界与操作反馈       |

密度调整主要改变 padding、gap 和辅助文字间距；不要缩小正文至不可读。圆角应影响可见容器，不应无差别作用于文字、图标或所有内部节点。关闭动效应停用自动动画，也要尊重系统 `prefers-reduced-motion`。

## 交互原则与反例

1. **让操作和反馈相邻。** 收藏反馈紧邻收藏按钮；避免操作发生在右上角、反馈却出现在页面底部。
2. **优先稳定内容。** 搜索条件变化后更新结果，不把用户焦点强制移到第一张卡片。
3. **渐进披露。** 卡片展示关键特征；技术细节、参数与复刻步骤放在详情中。
4. **信息不能只存在于 hover。** 手机和键盘用户也应看见分类、来源与操作。
5. **装饰不冒充功能。** 若终端只是模拟，说明模拟范围；若音乐组件没有音频，不显示虚假的播放承诺。
6. **保持可逆。** 收藏可取消、筛选可重置、模态可关闭、参数可恢复。
7. **真实处理失败。** 不用固定定时器展示“复制成功”，不把空搜索结果计入案例总数。

## 验收清单

下列项目是验收要求，只有执行后才能标记通过。

- [ ] 在 320、390、768、1440px 宽度下检查横向溢出、卡片内容与模态关闭按钮。
- [ ] 只用键盘完成该站实际提供的搜索、筛选、详情或其他核心任务；打开的面板能够关闭并恢复焦点。
- [ ] 声明持久化的收藏/购物袋在刷新后可恢复，删除后不复活，损坏存储不致崩溃；声明仅会话的功能则在刷新后重置，文案与行为一致。
- [ ] 输入不存在的关键词，出现真实无结果状态；清空后恢复内容。
- [ ] 每个可调参数至少测试最小、中间、最大三档，并核对预览变化。
- [ ] 开启减少动态效果，无持续漂浮、闪烁或强制平滑滚动。
- [ ] 复制失败路径不会谎报成功。
- [ ] 主要文本、焦点和控件状态达到对比度目标。
- [ ] 外链可辨识，来源核验状态与实际证据一致。
- [ ] 生产构建成功，浏览器无未处理异常；记录实际跑过的测试与未测项。

## 扩展案例的最小流程

先在资料表中添加原始链接和证据，再提炼三个可迁移原则。随后以原创文字和图形实现最小交互，补齐状态与手机布局，最后把参数、代码入口与验证结果写入案例说明。新增风格应增加可学习的设计方法，而不只是改变现有卡片的颜色。

## 独立站点的架构约束

每个站点都应包含完整的信息层次：品牌导航、主视觉、主要内容、次级说明、实际操作与页尾。不要用“一个预览卡片 + 几个风格按钮”代替完整网站。

- 独立入口：`apps/<site>/index.html`。
- 独立内容与状态：`apps/<site>/src/main.tsx`。
- 独立 CSS：`apps/<site>/src/styles.css`；不向其他站点导入全局主题。
- 独立构建产物：`dist/<site>`。
- 共享开发工具：根目录 Node 依赖、TypeScript 与 Vite；共享工具不等于共享运行时页面框架。

一个站点的通过结果不自动证明另一个站点通过。每个站都需要独立执行主要用户任务、窄屏检查和生产构建。资料目录可以链接到各站，但单独打开某个构建产物也必须完整运行。
