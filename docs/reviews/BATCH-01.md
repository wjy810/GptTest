# 第一批独立网站反刍：FOLIO / GRID 26 / MORI

复查日期：2026-11-17。对象为构建后的独立站 `editorial`、`swiss`、`organic`，使用本机 Chromium 访问 `http://127.0.0.1:4173/<站名>/`。这是项目开发过程中的交叉审阅，不是第三方无障碍认证，也不等同于真实用户研究。

## 1. 这一批要证明什么

三个站点各自有完整导航、内容组织、核心任务与页脚；不依赖总目录的壳层。FOLIO 的任务是读与收藏，GRID 的任务是了解展览并规划到访，MORI 的任务是选择商品并整理购物袋。因此，本轮同时检查“看起来是否有差别”和“按各自目标能否走完交互”。

复查的输入包括源代码、实际构建页面、1440 × 900 桌面视口、390 × 900 手机视口、键盘操作和受控异常状态。浏览器使用临时上下文，测试不会修改用户自己的购物袋或收藏。

## 2. 发现与已经完成的修复

| 发现 | 证据与原因 | 修改 | 复核 |
| --- | --- | --- | --- |
| FOLIO 和 MORI 都以深绿 + 米白为主，站点辨识度不足 | 并排查看整页截图，两者首屏都容易归入同一园艺/慢生活品牌 | FOLIO 正文改暖黑 `#342e32`，封面背景改深梅紫 `#322b38`，强调使用铜粉与米杏；MORI 保留自然绿 | 查看两尺寸截图；未改变 FOLIO 的编辑式分栏骨架 |
| FOLIO 星芒被系统渲染成彩色 emoji | 首屏和宣言区的 `✳` 受系统字体决定，颜色脱离设计系统 | 改用可控制尺寸与颜色的原创 SVG 放射形 | 桌面、手机截图均呈现一致铜粉色 |
| FOLIO 插画出现框内空边及暗泥感 | SVG 默认保持完整画幅，部分容器比例产生留边；黑色噪声覆盖使插画发灰 | 设置 `preserveAspectRatio="xMidYMid slice"`；移除可见黑噪声覆盖，保留极轻暖色层；第四篇使用蓝灰墙色 | 检查封面、文章卡片及阅读弹窗；插画填满容器，主图更明亮 |
| FOLIO 损坏收藏数据导致白屏 | 在临时上下文将 `folio-saved` 写为 `{}` 并刷新，实际报错 `H.includes is not a function`，页面正文为空 | 将解析值视为 `unknown`；先确认数组，再只保留真实文章 ID、去重；异常或错误类型回退为空数组 | 实测 `{}`、`null`、`1`、字符串、非法 JSON、混合重复数组共 6 种输入，均正常显示 |
| FOLIO 重复 SVG ID | 封面与首张卡片同时生成 `wall-sand`、`shadow-sand`、`noise-sand` | 每个 `Artwork` 使用 React `useId` 独立前缀 | 1440/390 DOM 扫描无重复 ID |
| FOLIO 阅读弹窗无可访问名称 | `dialog` 没有 `aria-label` / `aria-labelledby` | 用文章标题的 `reader-title` 命名弹窗 | 按名称定位“`一间房子，如何盛放安静`”成功 |
| FOLIO 阅读窗的焦点循环不明确 | 原生 dialog 最后一个控件 Tab 后，浏览器会经过文档焦点位置；首轮显式焦点断言失败 | 增加末尾到首个控件、首个 Shift+Tab 到末尾的循环；保留原生 dialog | 实测 Enter 打开、末尾 Tab 回到窗口内、Escape 关闭并回到触发按钮 |
| FOLIO / GRID 的窗口空白内边距会被当成遮罩 | 旧实现只比较 `target === currentTarget`，无法区分窗口内部空白与外部遮罩 | 再检查鼠标坐标是否位于 dialog 外边界；只在真正外侧关闭 | 代码检查并保留 Escape/关闭按钮流程；内边距点击边界未单独做自动化断言 |
| FOLIO / GRID 弹窗打开时背景仍允许滚动 | 原生 dialog 让背景不可交互，但不等于锁定背景滚动 | 打开期间记录并设置 `body.style.overflow='hidden'`，关闭时恢复 | FOLIO 开启/关闭后的 overflow 值实际断言通过；GRID 采用同一独立生命周期逻辑 |
| GRID 日期控件声明为 tabs，却没有方向键行为 | 聚焦 12.18 后按 ArrowRight，仍选中 12.18 | 实现左右循环、Home/End 与 roving tabindex；日程面板可聚焦 | ArrowRight→19、End→20、Home→18、ArrowLeft→20 全部实际通过 |
| FOLIO 手机文章元数据与收藏按钮偏小 | 390px 截图中元数据 7px，摘要 10px；书签按钮命中区域约 29px | 手机元数据调至 9px、摘要 12px、阅读时间 10px；收藏按钮命中区域至少 44×44px | 重建后重新拍摄 390px 截图，保留两列文章结构，无横向溢出 |

## 3. 实际执行的验证

执行过的命令：

```bash
npm run typecheck
npm run build -- --mode editorial
npm run build -- --mode swiss
node artifacts/reviews/verify-batch01.mjs
```

验证脚本需要已经构建三站并启动 `npm run preview`（默认端口 4173）；使用环境现有 `/usr/bin/chromium`，不下载浏览器。

最后一轮共 **22 组检查通过**，结果记录在 [after.json](../../artifacts/reviews/after.json)。这些组不是 22 个独立用户研究样本，单组可能包含多个断言。

- **三站共同检查**：1440px 与 390px 都只有一个主标题；页面无横向溢出；不存在重复 DOM ID；减少动态效果偏好下不启用平滑滚动；本轮无页面 JavaScript 异常。
- **FOLIO**：异常收藏数据恢复、命名阅读弹窗、Enter/Tab/Escape、关闭后焦点恢复、分类筛选、收藏跨刷新保留、取消最后一篇收藏后的空状态、本地订阅反馈。
- **GRID 26**：方向键/Home/End 日期导航、每个日期三场活动、命名展览详情、关闭焦点恢复、三日票两人总额 `¥316`、禁用单日日期选择、本地预约摘要包含三日范围。
- **MORI**：植物分类结果三件、命名商品详情、一件橡皮树含运费 `¥186`、两件达包邮为 `¥336`、购物袋跨刷新保留、本地订单摘要、Escape 恢复焦点、手机导航关闭、原生 FAQ 展开。

## 4. 三个独立站的差异在哪里

| 维度 | FOLIO 编辑杂志 | GRID 26 展览 | MORI 生活品牌 |
| --- | --- | --- | --- |
| 情绪 | 安静、思辨、纸刊式 | 强烈、秩序感、公共文化 | 自然、温和、可以触摸 |
| 视觉识别 | 梅紫封面、铜粉强调、英文衬线字标 | 大面积红、暖黑、几何海报、无衬线大字 | 米白、植物绿、拱形背景、陶土与植物插画 |
| 内容结构 | 封面文章 → 阅读列表 → 观点 → 来信 | 展览主张 → 三展览 → 活动日程 → 票务 | 生长场景 → 商品 → 品牌故事 → 养护 → 常见问题 |
| 主要任务 | 打开文章、收藏、回到书架 | 挑日期、查看活动、选择通行证 | 找商品、看说明、修改购物袋 |
| 节奏 | 双栏封面与留白，文字承担主体 | 数字、网格、横线建立明确节奏 | 曲线轮廓、柔色商品图、较慢段落过渡 |
| 状态设计 | 分类、收藏空状态、阅读弹窗 | 日期 tab、票种 radio、预约摘要 | 类别筛选、购物袋、运费阈值、订单摘要 |

不能只换颜色和字体就说是三个风格。这里真正决定差异的是任务流、内容密度、页面分段与主操作。配色只是让这种差异在第一眼更明显。

## 5. 从这一批带到下一批的原则

1. **每个独立网站先写清楚一个主要任务。** 阅读站不需要购物抽屉，展览站不需要无限瀑布流；组件由任务决定。
2. **把邻近风格并排比较。** 都使用米白并不构成问题，但若首屏色块、插画与字重都接近，就需要改变至少两项识别轴。本轮保留 FOLIO 纸感，改变封面色与阅读气质。
3. **SVG 是组件资源，不是全局命名空间。** 重用插画时必须给渐变、蒙版、滤镜分配实例 ID；容器覆盖由 `preserveAspectRatio` 处理，而不是依靠对 SVG 不生效的图片习惯。
4. **本地存储也属于不可信输入。** 不只有 JSON 语法损坏；合法 JSON 的错误类型、失效 ID、重复项一样需要恢复策略。不要让用户手工清理浏览器才能继续用。
5. **声明了交互语义就完成对应行为。** `role="tab"` 要有方向键、选中状态与焦点管理；若只是三个筛选按钮，则使用普通按钮和 `aria-pressed` 更简单。
6. **模态窗需要一个完整生命周期。** 可访问名称、首次焦点、循环焦点、Escape、遮罩边界、背景滚动和关闭后恢复焦点要一起检查。
7. **移动端检查不止是“不溢出”。** 字号是否还能读、点击区域是否够大、内容是否变成过长碎行，都要在截图中复核。本轮没有用整页缩放来伪造适配。
8. **用具体金额或结果验证任务。** `¥168 + ¥18 = ¥186` 与两件包邮 `¥336` 比“购物袋能打开”更有验证价值；`¥158 × 2 = ¥316` 比“按钮可点击”更接近用户目标。
9. **复盘记录要保留失败与边界。** 焦点检查曾失败，就记录失败和修复；没有做屏幕阅读器测试，就明确未做。设计样例不需要假装具备真实商业后端。
