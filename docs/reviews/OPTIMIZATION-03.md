# 第三批优化独立复盘：EMBER / ROAM / P1XEL

日期：2026-11-17。本轮只读检查冻结后的生产页面与截图，重点是320/390px的阅读、控件放大和既有菜单、规划、游戏流程。未修改站点源码或 Git。

**状态：第三批独立轻量复核通过。** 三站的重点变化没有产生新的阻塞回退。作者专项与根代理正式套件分别记录，不计为本次独立检查。

## EMBER：菜品信息与预约控件一起变得清晰

手机食材说明从9px增至12px，菜单和预约规则增至12px；人数增减按钮为44×44，日期与时间控件为16px字号、48px高。420px以下日期与时间上下排列，360px以下价格移到菜名下方，保留双列餐盘而不挤压文字。

独立查看320/390整页后图：320px菜名、价格、食材分层完整，较长食材说明自然换行；390px有足够空间让价格与菜名同行。放大的预约字段没有遮挡规则或提交入口，酒红与奶油色的餐厅视觉保持不变。

生产320px实测文档宽度320，食材12px，人数按钮44×44，日期和时间输入均16px/48px、宽241.625px。键盘focus→Enter选择甜品后，列表准确显示“炉烤无花果”“焦糖梨与香草”两道；键盘增加人数后显示3位，日期字段可以取得焦点。没有重复作者已完成的跨日、休息日与预约摘要完整用例。

阅读和输入区域扩大使390px页面高度从4149增至4367。这里接受必要的纵向增长，收益是食材、规则与预约操作可读可用，而非单纯压缩页面。

## ROAM：缩短重复景观段落，让规划更容易到达

手机目的地景观图由固定250px改为随宽度调整：390px时约191px，320px时160px；卡片间距32→26px，正文没有跟随缩小。列表末尾增加“先算一份旅行预算”直达已有规划区。选择框手机字号16px，人数和天数操作高度至少44px；320px人数与天数上下排列，避免互相抢空间。

按作者使用同一`#plan`选择器的前后测量，390px规划区顶部从y=5539.6前移至5158.7，前移约381px；320px从5631.2前移至5017.8，前移约613px。390px页面总高6939→6584，320px7078→6655。这里比较的是同一个section边界，没有把标题与section位置混算。

独立查看320px六张目的地卡片和390px规划表单后图：景观、收藏、名称和价格层级完整，规划规则没有被控件遮盖。生产320/390px文档宽度均与视口一致；320px景观图实测160px，选择框16px/49px，人数按钮44×44。

实际点击新预算入口后，`#plan`位于视口顶部29.75px。键盘人数2→3使默认川西预算¥6,600→¥9,900，天数5→6使预算变为¥11,160；生成草案准确显示3人、6天、金额与公式，Esc关闭后焦点回到生成按钮。无浏览器脚本错误。金额仍为本地演示参考值，没有发生真实预订。

## P1XEL：把卡片操作移到稳定位置，游戏反馈更易读

游戏卡片将主操作与收藏放在独立底部操作行，按钮高度44px；收藏和挑战重置均44×44。这样保留双列海报与游戏标题，同时避免放大的收藏按钮挤压名称。挑战反馈文字增至14–15px，规则和战绩说明也提高了可读性。

独立查看320px游戏大厅、320/390px挑战区与320px四位成绩截图：操作行不压住描述，等待/开始说明完整，数值与毫秒单位都在指标卡内。生产320px实测主操作84×44，收藏与重置44×44；四张卡片操作行均`clientWidth=scrollWidth=134`。320/390px文档没有横向溢出，390px屏幕反馈文字为15px。

实际键盘focus→Enter从首屏进入挑战后，焦点落在游戏屏幕；Enter开始等待，变绿后再次Enter，记录一轮1697ms。两张指标卡均`clientWidth=scrollWidth=132`，数值边界在卡片内。键盘重置使游戏回到初始状态并保留这一条战绩。无浏览器脚本错误。反应时间是自动化操作产生的演示记录，不是人的反应能力测量。

作者在生成后图时发现并修复了320px四位毫秒数值撑出指标卡的问题；本次独立检查用真实产生的四位成绩再次确认修后边界。当前站点仍是一个可玩反应挑战加三个规则概念，未扩大功能范围。

## 发现与结论

- EMBER通过调整价格和表单排列承接字号、点击区的增长，保持菜单信息完整。
- ROAM缩小重复景观图幅，并在浏览结束处提供规划入口，减少手机滚动负担；计算和草案反馈仍一致。
- P1XEL配套重排卡片操作，并修正四位成绩的内部溢出；页面宽度正常之外，也检查了卡片内部边界。
- 三站独立轻量复核没有发现新的阻塞问题，可在根代理正式批次检查通过后进入第四批。
