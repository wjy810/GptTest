## 4. 下一批继续使用的原则

1. **先决定信息组织，再决定视觉装饰。** 数据工作台适合紧凑比较，公共服务需要快速找到任务，建筑项目需要观察空间；它们应有不同的首屏和阅读速度。
2. **CSS 命名也要验证数据驱动的组合。** 一个合法场景值 gallery 与容器同名，就能在没有报错或横向溢出的情况下破坏布局；截图与组件尺寸能发现这种问题。
3. **默认数据和主动清空是两个状态。** 初次无键可以展示示例，用户写入空数组必须保持为空；不能让初始化逻辑撤销用户操作。
4. **界面移除焦点元素时安排接续目标。** 搜索清除、空态消失、导航收起、模态进入下一任务，都需要具体目的地。
5. **验证数字要用另一条可解释路径。** 用逐月台账复算公式，用实际 CSV 逐行对照表格，用日期比例对照 SVG 坐标，避免测试只重复实现。
6. **局部横滚必须可发现、可聚焦、可操作。** 页面不溢出只是开始；手机截断的列也需要提示，键盘应能进入滚动区域。
7. **原生校验与业务校验相互补充。** required 不能拒绝纯空白，min 不能取代提交阶段的日期规则；本地演示同样要让输入和输出一致。
8. **把复刻文档绑定到真实源码。** 持久化键、单位、函数名、输入边界与演示范围都能在代码中找到，并随复查结果更新。
