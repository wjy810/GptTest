# 持续研究与扩展协议

这个仓库是一组各自独立的网站，不是一套皮肤切换器。目录只提供跳转；每个站点必须有自己的 HTML 入口、导航、内容结构、视觉规范、CSS、核心交互与构建产物。

## 固定工作节奏

1. 每批选择三个方向，先记录用户任务、风格假设和真实研究来源。
2. 完成一个可运行的完整网站：首屏、内容区、核心任务、边界状态、页脚、手机适配。
3. 单站构建与关键操作通过后，使用独立 Git 提交上传 GitHub。推送前读取远端变化，不覆盖他人工作。
4. 每完成三套，暂停增加样例，回看本批三套的完整桌面与手机截图。
5. 审核布局、风格差异、文字可读性、信息完整性、交互反馈、键盘、降动效和坏数据恢复。把发现、修复和实测证据写入 `docs/reviews/BATCH-XX.md`。
6. 重新构建受影响站点，运行对应测试，将修复追加提交，再开始下一批。

不能把还没做完的站、没有运行的测试、无法访问的视频写成完成。截图美观只是其中一项，不能代替任务可用性。

## 可复用性要求

- 保存研究结论和代码位置，不能只写“参考某风格”。
- 每站尽量使用自有图形与字体回退；第三方资源必须记录来源与许可。
- 使用 `npm run dev -- --mode <site>` 和 `npm run build -- --mode <site>` 独立运行。
- 在 `sites.json` 登记新的独立入口（开发端口为 5173 加索引）；该清单供 Vite、批量构建与多站开发进程共用，不提供网站运行时外框。同步更新资料目录卡片与测试后，检查目录链接和完整生产构建。
- 一次会话结束不等于后台任务在继续。后续任务从最近的审核记录和 Git 提交继续，不凭空宣称自动持续研究。
